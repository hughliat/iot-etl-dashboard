# 02-PRD — IoT 传感器数据 ETL 与可视化项目

## 1. 非目标（Non-goals）

本期明确不做：

- 不接真实硬件、真实传感器、真实天气 API。
- 不做云端部署、用户登录、权限控制。
- 不做实时流式处理，仅离线批处理。
- 不上企业级数仓引擎（Hive、Spark、Doris 等），分层仅用 SQLite schema 命名体现。
- 不接入本机九域工作台（独立 GitHub 展示仓库）。

## 3. 功能详述

**采集模拟（REQ-01、REQ-02、REQ-10）**

- 作为项目所有者，我希望一键生成可复现的多站点传感器数据，以便在面试中快速演示完整链路。
- 作为项目所有者，我希望数据带站点与设备维度，以便展示多站点对比分析。

业务规则：

- 传感器类型：温度（℃）、湿度（%RH）、气压（hPa）、PM2.5（μg/m³）。
- 合理值范围：温度 -30 ~ 50 ℃；湿度 0 ~ 100 %RH；气压 870 ~ 1085 hPa；PM2.5 0 ~ 500 μg/m³。
- 确定性随机：固定随机种子，同参数多次运行生成完全一致的数据。
- 脏数据注入：按小比例注入重复行、越界值、缺失值，用于演示清洗必要性。
- 站点与设备数、采样频率、时长默认值由开发设计确定（见开放问题）。

**ETL 清洗（REQ-03）**

- 作为项目所有者，我希望 ODS 原始数据被清洗为 DWD 明细，以便向面试官展示清洗方法论。

业务规则：

- 去重：按业务主键（站点 + 设备 + 时间戳）去重。
- 异常值：越界值置空并标记异常状态，不静默丢弃。
- 单位统一：统一为国际单位（℃、%RH、hPa、μg/m³）。
- 字段规范化：时间戳统一为 UTC 或本地时区一致格式，字段命名统一。

**指标聚合（REQ-04）**

- 作为项目所有者，我希望明细按小时 / 天聚合为指标集市，以便展示指标加工能力。

业务规则：

- 小时粒度：每站点每设备每小时，输出均值、最大值、最小值、标准差。
- 天粒度：每站点每设备每天，输出均值、最大值、最小值、标准差。
- ADS 层：生成看板直接消费的指标宽表。

**看板输出（REQ-05、REQ-12）**

- 作为项目所有者，我希望看板离线可打开，以便在任意环境演示。
- 作为招聘方，我希望看板直接展示趋势与多站点对比，以便快速理解数据。

业务规则：

- 图表为内嵌 SVG，无 CDN 依赖，离线可用。
- 至少展示温度 / 湿度 / 气压 / PM2.5 的时序趋势与站点对比。
- 站点筛选、时间范围切换为 P1 交互增强。

**SQL 优化对比（REQ-07）**

- 作为项目所有者，我希望 README 中有 SQL 优化的量化对比，以便呼应实习「BI 查询提速」亮点。

业务规则：

- 选一个典型慢查询场景（如「某站点近 7 天 PM2.5 每小时均值」）。
- 分别执行朴素 SQL 与「加索引 + 重写」SQL，输出 `EXPLAIN QUERY PLAN` 结果与多轮计时均值。
- 对比结果落盘到文件，供 README 引用；量化数字由实际运行得出，不预设。

**一键运行与 README（REQ-06、REQ-08、REQ-13）**

- 作为招聘方，我希望在全新环境执行一条命令即可得到数据库与看板，以便快速评估。

业务规则：

- `make run` 顺序执行采集 → ETL → 优化对比 → 看板输出，产出数据库 + 看板。
- README 含架构图、分层说明、快速开始、SQL 优化亮点、测试说明。

## 4. 非功能需求

| 项 | 要求 |
|---|---|
| 可复现性 | 同参数同种子多次运行，数据与指标结果完全一致 |
| 性能 | SQL 优化对比在压测规模下数秒级内完成（具体阈值由开发设计定） |
| 兼容性 | 跨平台（Windows / macOS / Linux）；Python 版本下限由开发设计定 |
| 离线可用 | 看板无 CDN、无外链，断网可打开 |
| 可维护性 | 代码遵循 PEP 8，函数单一职责，核心 ETL 逻辑可单测 |
| 数据安全 | 无真实数据、无密钥、无账号，中间产物 gitignore |

## 5. 验收标准

- **REQ-01**：给定一个固定种子与站点 / 设备 / 时长参数，当执行采集，那么两次运行生成的数据逐行一致；且数据中同时包含温度、湿度、气压、PM2.5 四类字段，并存在可识别的脏数据（重复行 / 越界值 / 缺失值至少两类）。
- **REQ-02**：给定采集完成，当写入 SQLite，那么存在 `ods_sensor_raw` 表，行数与生成量一致，字段含站点、设备、时间戳与四类传感器读数。
- **REQ-03**：给定含重复行、越界值、缺失值的 ODS 数据，当执行清洗，那么 DWD 无重复主键、越界值被置空并标记、字段单位与命名统一。
- **REQ-04**：给定 DWD 明细，当执行聚合，那么 DWS 按小时 / 天输出均值、最大、最小、标准差，且抽样数值与手工计算一致。
- **REQ-05**：给定 ADS 指标，当执行看板输出，那么生成 JSON 与 HTML 文件，HTML 在断网状态下可直接打开并显示四类指标趋势与站点对比。
- **REQ-06**：给定全新环境与已安装依赖，当执行 `make run`，那么顺序产出 SQLite 数据库、看板 HTML、看板 JSON，无报错退出。
- **REQ-07**：给定压测规模数据，当执行优化对比，那么输出朴素 SQL 与优化 SQL 的 EXPLAIN QUERY PLAN 结果（可见 SCAN 到 SEARCH 的变化）与计时对比，且结果落盘。
- **REQ-08**：给定仓库，当阅读 README，那么包含架构图、分层说明、快速开始、SQL 优化量化亮点、测试说明五部分。
- **REQ-09**：给定测试套件，当执行 `make test`，那么全部用例通过，且用例覆盖去重、异常值处理、聚合三类核心逻辑。
- **REQ-10**：给定站点 / 设备元数据表，当查询，那么可按站点维度汇总与对比。
- **REQ-11**：给定清洗前后数据，当执行质量报告，那么输出清洗前行数、清洗后行数、异常值统计。
- **REQ-12**：给定看板，当切换站点或时间范围，那么图表按所选维度刷新。
- **REQ-13**：给定全新环境，当按 README 安装依赖并执行 Makefile 目标，那么 `make run` 与 `make test` 均可用。

REQ-14、REQ-15、REQ-16 为 P2，验收标准在启动开发时再细化。
